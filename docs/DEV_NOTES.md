## 1. 阶梯降阈 · 状态检测表（hash 模式）

对预置的 1 张经验卡 + 2 个记忆网节点，用 5 句测试（2 技术报错应 exp、2 知识应 net、1 闲聊应 skip/回退），逐档降低 `sim_threshold`，测得：

| 阈值 | 触发次数 | 回退 | 召回率 | 污染率 | 判定 |
|---|---|---|---|---|---|
| 0.85 | 0 | 5 | 0% | 0% | 可接受（但过保守） |
| 0.75 | 0 | 5 | 0% | 0% | 可接受（但过保守） |
| 0.70 | 0 | 5 | 0% | 0% | 可接受（但过保守） |
| 0.60 | 0 | 5 | 0% | 0% | 可接受（但过保守） |

**结论**：污染率始终 0（不会误判闲聊），但召回率也始终 0——**降低阈值并不能让默认 hash 模式主动分诊**。

## 2. hash 相似度上限 ≈ 0.40–0.43

对近乎精确的查询（如"版本检查机制" vs 节点"服务端的版本检查机制会定时向网络请求…"），实测相似度最高约 **0.433**；即便把阈值降到 **0.50** 仍低于该值，无法触发。

**根本原因**：默认哈希向量是**确定性词袋式**，无语义泛化；相似度在此类内容上封顶约 0.4–0.5。

**这意味着**：
- 默认 `sim_threshold: 0.85` 在 hash 模式下几乎永不触发（多数话交还主模型），属"安全但不主动"；
- **仅靠降阈值（0.85→0.60）无法获得主动分诊**，且再往下降（<0.43）会开始把低相关噪音拉进来（污染率上升）；
- 要真正提升主动分诊，需：**① 切换 bge-m3 语义嵌入**（相似度可到 0.5–0.7，配 `bge_sim_threshold: 0.72`）；或 **② 使用本地小模型管家 `triage_brain: qwen`**（三分类硬判，绕过阈值）。

## 3. 推荐做法（供高阶调参）

| 目标 | 做法 |
|---|---|
| 零依赖、够用 | 保持 `hash` + 默认 0.85（保守，多数交还主模型） |
| 提升召回/主动分诊 | 装 bge-m3：`embedding_provider: "bge"` + 模型路径/端点，阈值用 `bge_sim_threshold` |
| 最主动分诊 | `triage_brain: "qwen"`，本地小模型三分诊（net/exp/skip） |

> 注：`nav_max_entries` / `nav_max_chars`（导航注入上限，默认 120 / 4000）是"伪无限上下文"的理论上限护栏，属另一套调参项，见 README 正文。
